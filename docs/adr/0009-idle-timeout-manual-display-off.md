# 0009 手動消灯にWindowsの自動画面オフを使用する

- 状態：Accepted
- 日付：2026-07-31
- 置き換える判断：`0005-manual-display-off.md`のWindows API選択

## 文脈

ADR 0005では、手動ディスプレイ消灯に`SC_MONITORPOWER`を採用しました。
しかし、Modern Standby対応機でバッテリー駆動中にこの操作を行うと、`SystemRequired`要求が存在していても、通常のデスクトップ処理が消灯から約5秒後に停止しました。
ネットワークも約12秒後に切断され、Codexのようなデスクトップ処理を継続できませんでした。

同じ機器と電源条件でも、Windowsのアイドルタイムアウトによる自動画面オフでは、Modern Standby開始イベント後も10分間、診断プローブが動作しました。
`VIDEOIDLE`を1秒へ変更し、画面消灯後に元の値へ戻す試験でも、画面は再点灯せず、通常設定を復元できました。

## 判断

「ディスプレイをオフ」は、`SC_MONITORPOWER`を使用せず、現在の電源プランにある現在の電源側の`VIDEOIDLE`を1秒へ一時変更して実行します。
変更から5秒後に、対象の`VIDEOIDLE`が1秒のままである場合だけ、変更前の値へ戻します。

一時変更では`STANDBYIDLE`、反対側の電源設定、DisplayLightの保存設定を変更しません。
途中で電源プランが切り替わった場合は、元のプランを再び有効化せず、そのプランに保存された値だけを復元します。
例外時とアプリ終了時にも復元を試みます。
一時変更前に復旧に必要な電源プラン、対象電源側、元の秒数をローカルへ保存し、強制終了した場合は次回起動時に条件付きで復元します。

3秒のカウントダウン、キャンセル条件、フライアウトを閉じてから実行する順序はADR 0005の判断を維持します。

## 結果

手動消灯はWindowsの`Idle Timeout`として扱われるため、実機検証ではバッテリー駆動中も通常のデスクトップ処理を継続できました。
一時変更は通常設定と同じWindows値を共有するため、復元前に値を読み直し、外部からの新しい変更を上書きしません。

アプリの通常終了と処理中の例外には復元処理を実行できます。
プロセスを強制終了した場合も、次回起動時に復旧情報を読み取り、対象値が1秒のままである場合だけ元の値へ戻します。
次回起動まで1秒設定が残る時間をなくす必要が生じた場合は、親プロセスを監視する別プロセスを追加する余地があります。

## 比較した案

`SC_MONITORPOWER`は通常の設定値を変更しませんが、検証対象機のバッテリー駆動ではデスクトップ処理が停止するため採用しません。

`DisplayRequired`と最低輝度または黒画面を組み合わせる方法は、論理ディスプレイをオンに保つため処理継続を期待できます。
ただし、物理的な消灯を保証せず、外部ディスプレイの制御も機器に依存するため、今回の手動消灯には採用しません。
